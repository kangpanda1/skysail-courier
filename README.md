# Skysail Courier — fly a bush plane over a generated fjord

A 3D flight game about hauling mail between gravel strips on a fjord coast. Plain static files: no
build step, no bundler, no network. Open `game/index.html` in a desktop browser, or serve the
folder and play it at http://localhost:8080.

    node serve.ts        # serves game/ and opens it

Three.js r160 is vendored at `game/vendor/three.module.min.js` (the official npm build, with two
local edits: `createElementNS` for the HTML namespace replaced by `createElement`, and a deprecation
warning's URL replaced by prose, so nothing in the shipped files carries a remote reference).
Everything else — the fjord, the aircraft, the sky, the instruments and the sound — is generated by
the code in `game/src/` from one seed. There is no art asset and no audio file in the repository.

## What you fly

A 1,180 kg taildragger with a 225 hp radial, 96 litres of fuel and tundra tyres. The flight model is
an energy-state model in `game/src/flight-model.js`: lift from angle of attack and dynamic pressure,
induced drag off the same lift, propeller thrust falling with density, ground handling with a tail
that comes up, a wing that lets go at 14 degrees and keeps 62 % of its lift past the stall so a stall
is a controlled descent rather than a fall. Fuel is a real constraint: about twenty minutes of
bush-work, so a detour is a decision.

## Missions

* **Courier haul** — lift a crate at one strip, set it down on another, twice over. Scored on time
  and on how the aircraft was landed: sink rate, centreline, rollout.
* **Ring course** — nine hoops strung across the coast, each one worth a pass.
* **Storm rescue** — an IFR flight to a flare on the water in driving rain, then a survivor carried
  back to a gravel bench before the tank runs dry.

Best score per mission is kept in `localStorage`.

## Controls

| Key | |
|---|---|
| `R` / `F` | throttle up / down |
| `↑` `↓` or `W` `S` | elevator |
| `←` `→` or `A` `D` | aileron |
| `Q` / `E` | rudder |
| `V` | flaps |
| `T` | trim reset |
| `C` | camera: chase, cockpit, orbit |
| `P` | autopilot (flies the approach with the same controller the screenshots were staged with) |
| `O` | pause |
| `[` `]` | previous / next mission |
| `Enter` | restart |
| `/` or `H` | help |

## Layout

    main.ts                  hands game/ and screenshots/ to the judge and writes dossier.json
    serve.ts                 static server for local play
    shots.json               what each screenshot is a capture of, by URL
    game/index.html          the page: two canvases and no markup beyond them
    game/src/config.js       every tunable number and colour
    game/src/rng.js          hashed value noise, fbm and ridging — deterministic, no Math.random
    game/src/world.js        height field, terrain mesh, water, trees, scree, the strips and their valleys
    game/src/sky.js          gradient dome, sun bloom, cloud banks, fog and rain per weather preset
    game/src/aircraft.js     the airframe: lathe fuselage, greenhouse cabin, high wing with flying wires, radial
    game/src/flight-model.js the physics, with no dependency on the renderer
    game/src/controls.js     rate-limited axes, flap and trim servos, autopilot hook
    game/src/camera.js       chase, cockpit and orbit rigs that refuse to put the eye in a hillside
    game/src/instruments.js  the six-pack, drawn to a canvas as 2D vectors
    game/src/hud.js          speed and altitude tapes, heading ribbon, target arrow, warnings, landing grade
    game/src/missions.js     the three missions, their scoring and their objectives
    game/src/audio.js        engine, propwash, wind and radio, synthesised in WebAudio
    game/src/render.js       the stage: renderer, tone mapping, shadow map, detail streaming
    game/src/scenes.js       the posed scenes the screenshots are captures of
    game/src/main.js         boot, fixed-timestep loop, key handling

## Reproducibility

The world is a function of one seed (`20261126`) and the simulation steps at a fixed 1/60 s, so the
same scene renders the same frame every time: `?shot=cover`, `?shot=cockpit`, `?shot=storm` and
`?shot=delivery` stage a real run of the game's own physics and stop it at the frame each screenshot
shows. Nothing in the game calls `Math.random`.
